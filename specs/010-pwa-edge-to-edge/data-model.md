# Phase 1 Data Model: PWA & Edge-to-Edge

This feature persists **no** user/server data. The "entities" are static configuration and derived client-only artifacts.

## Static configuration entities

### App Install Metadata (web app manifest)

Served by `app/manifest.ts` at `/manifest.webmanifest`.

| Field | Value | Notes |
|-------|-------|-------|
| `name` | "TaskFlow" | full name on install UI / splash |
| `short_name` | "TaskFlow" | home-screen label |
| `start_url` | "/boards" | installed launch target; auth guard sends to /login if needed |
| `display` | "standalone" | no browser chrome when launched |
| `background_color` | `#0D1117` | splash background (dark baseline) |
| `theme_color` | `#0D1117` | manifest theme (dark baseline; per-theme handled via viewport.themeColor) |
| `icons` | `[{192}, {512}, {512 maskable}]` | references generated icons; maskable has safe padding |

### Apple / viewport meta (root layout)

| Surface | Value |
|---------|-------|
| `viewport.themeColor` | `[{ media: "(prefers-color-scheme: dark)", color: "#0D1117" }, { media: "(prefers-color-scheme: light)", color: "#EAEEF4" }]` |
| `viewport.viewportFit` | `"cover"` |
| `apple-mobile-web-app-capable` | `yes` |
| `apple-mobile-web-app-status-bar-style` | `black-translucent` |
| `apple-mobile-web-app-title` | `TaskFlow` |
| `apple-touch-icon` | generated by `app/apple-icon.tsx` |

### Generated icons

| File | Output | Purpose |
|------|--------|---------|
| `app/icon.tsx` | 512 PNG (ImageResponse) | favicon/app icon, brand grid glyph on accent gradient |
| `app/apple-icon.tsx` | 180 PNG (ImageResponse) | iOS home-screen touch icon |
| manifest `512 maskable` | from icon, padded | Android adaptive icon (no crop) |

## Client-only derived artifacts (not persisted server-side)

### Cached App Shell (Cache Storage)

| Property | Value |
|----------|-------|
| Cache name | `taskflow-shell-v{N}` (version bumped per release) |
| Contents | app shell HTML/JS/CSS for navigations + `/offline` + `/_next/static/*` + icons/fonts |
| **Excluded** | `/api/*` responses, auth tokens/cookies, any mutable board/task data, cross-origin |
| Eviction | old `taskflow-shell-v*` caches deleted on `activate` of a new version |

**Rule**: the cache holds only the static shell + offline page. It is never a source of truth for application data — REST is. Offline shows the shell/offline screen, not stale data presented as live.

### Fallback Screens (presentational, derived)

| Screen | File | Trigger |
|--------|------|---------|
| Offline | `app/offline/page.tsx` | SW navigation fallback when network unavailable |
| Error | `app/error.tsx` (+ `global-error.tsx`) | a route/component throws during render |
| Not found | `app/not-found.tsx` | unknown path |

All reuse `EmptyState` + glass, are bilingual (AR فصحى/EN), mirror in RTL, respect reduced-motion/transparency, and mark their message `role="alert"`.

## State transitions

**Service worker lifecycle**: `install` (precache shell, skipWaiting) → `activate` (drop old version caches, claim clients) → `fetch` (route per strategy). On a new deploy: new version installs → skipWaiting/claim → registrar observes `controllerchange` → one reload → user on fresh shell. No persisted app state changes.
